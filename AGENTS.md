# XRM implementation

Xtext implementation of the Expressive RDF Mapper DSL. User docs live in
[zazuko/expressive-rdf-mapper](https://github.com/zazuko/expressive-rdf-mapper).

## Layout

- `com.zazuko.rdfmapping.dsl.parent/com.zazuko.rdfmapping.dsl/` – grammar (`RdfMapping.xtext`), validation, scoping, generators (RML, R2RML, CARML, CSVW)
- `com.zazuko.rdfmapping.dsl.parent/com.zazuko.rdfmapping.dsl.ide/` – language server and the CLI (`ide/cli/XrmCli.java`)
- `com.zazuko.rdfmapping.dsl.parent/com.zazuko.rdfmapping.dsl.tests/` – unit tests
- `runtime-EclipseXtext/` – sample projects; each `src-gen/` holds the expected generator output
- `src-gen/`, `xtend-gen/`, `model/generated/` are generated by the build; never edit them

## Build and test (Docker only, no local Java/Maven needed)

```sh
cd com.zazuko.rdfmapping.dsl.parent
docker volume create xrm-m2
docker run --rm -v xrm-m2:/root/.m2 -v "$PWD/..":/src -w /src/com.zazuko.rdfmapping.dsl.parent \
  maven:3.9.16-eclipse-temurin-17 mvn -B verify \
  -pl com.zazuko.rdfmapping.dsl.target,com.zazuko.rdfmapping.dsl,com.zazuko.rdfmapping.dsl.ide,com.zazuko.rdfmapping.dsl.tests
```

The UI modules (`*.ui`, `*.ui.tests`) need an Eclipse/display environment; leave them out unless working on the Eclipse plugin.

Regression check against the samples (after building the image with `docker build -t xrm .`):

```sh
XRM_IMAGE=xrm scripts/check-samples.sh
```

If a generator change intentionally alters output, regenerate the samples'
`src-gen/` with the CLI and commit them together with the change.
